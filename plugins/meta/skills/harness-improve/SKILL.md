# harness-improve

このスキルは、レトロスペクティブの後半を行う。retrospective が各タスクで残した振り返りを並べ、繰り返している理由を見つけて、何を変えるかを決め、指示ファイルや hook などを直す。

## 並べる

まだ扱っていない振り返りの件と、前回までに様子見にした件を並べる。どれがまだ扱っていない件かは、「残す」の形で分かる。

並べた件は、表面の出来事ではなく、期待と分かれた判断でまとめる。その時点で何を知っていて、何を良しとしてそう判断したかが同じなら、違う作業で起きた違う出来事でも一つのまとまりにする。直す相手は、一件の出来事ではなく、その判断を繰り返させているものである。一件ずつ直すと、指示ファイルに個別の事例が溜まって、ほかの指示が読まれにくくなる。

振り返りに判断が書かれていない件や、書かれた判断がまとまりを決める決め手になる件は、そのセッションのログで確かめる。振り返りの判断も、書いたセッションの読みである。

## 決める

繰り返しているもの、一度でも取り返しのつかない結果になりうるもの（データを失う、秘密が漏れる、公開される）は、直す案を出す。一度だけで重大でもないものは様子見にし、もう起きなくなったものは様子見から外す。繰り返し良いと言われている判断がどの指示にも書かれていなければ、書く案を出す。

直す案は、まとまりの判断が変わるものにする。そう判断させているのは、指示の文だけでなく、モデルの既定の振る舞い、指示どうしの組み合わせ、作業の進め方のこともある。何がその判断を良しとさせたかを突き止め、そこを変える。

判断を良しとさせているのが、すでにある指示の文であることは多い。一件の訂正を、目的も当てはまる場面も添えずに言い切った文は、エージェントには目的と関係なく守る制約として読まれ、外れた場面で別の訂正を生む。そこに例外を書き足すと、同じことが例外の外で起きる。だから、まず消すか、目的と一緒に書き直すことを考え、書き足すのは、どの指示にもない判断の材料が要るときにする。直したあとは、指示が減ったか、少なくとも増えていないかも見る。

期待と違う行動を hook や permissions で止めるのは、判断は変えずに結果だけを防ぐ手なので、取り返しのつかない結果を確実に防ぐ必要があるときに限る。指示や仕組みが判断にどう効くかは [${CLAUDE_SKILL_DIR}/../../reference/instruction-files.md](${CLAUDE_SKILL_DIR}/../../reference/instruction-files.md) にまとめてある。関係する指示があったのに判断が変わらなかったなら、その指示がそのときコンテキストにあったかをログで確かめる。読み込まれていなかった指示は、文面をいくら強くしても変わらない。以前に却下された提案と同じ理由なら、却下の理由を踏まえる。

案ごとに、もとになった件（件数、日付、引用）、どの判断のどこを変えるか、そのために何をどう変えるか（消す・書き直す文と、足す文）を示す。直さないまとまりも理由と一緒に示す。どれを直すかはユーザーが決める。

## 直す

了承された案は、meta スキルに従って直し、確かめる。

## 残す

どこまで扱ったかは、振り返りではなく、harness-improve の記録で持つ。振り返りは書き換えない。

- 振り返りは、各タスクの記録の隣にある `retrospective.md` で終わるファイルで、`##` 見出しの一つが一件にあたる
- harness-improve の記録は、実行するたびに自分のタスクの記録として書く。名前は `harness-improve.md` で終わり、ほかと重ならないものにし（付け方はユーザーの指示に従い、決まりがなければタスクの名前を頭に付ける）、先頭に日付を書く
- 並べた件は、`## 結果`（直した、却下された、もう起きない）か `## 様子見` の下に、`[[<振り返りの拡張子を除いたファイル名>#<見出し>]]` の形で一度ずつ出す。どの記録にも出てこない件が、まだ扱っていない件になる
- `## 様子見` には、同じ理由の件をまとめて回数と日付を書き、前の記録の様子見で続けるものも書き写す。次は、いちばん新しい記録の様子見だけを読めばよい
- 了承されたのに直し終えられなかった件はリンクにせず、次に読み直させる

どちらもタスクの記録の置き場所にある。置き場所はユーザーの指示ファイルに従い、書いていなければユーザーに聞く。

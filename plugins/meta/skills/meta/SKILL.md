# 指示ファイルを書く・直す

指示ファイルがエージェントの判断にどう効くかは [${CLAUDE_SKILL_DIR}/../../reference/instruction-files.md](${CLAUDE_SKILL_DIR}/../../reference/instruction-files.md) にまとめてある。読み込まれ方やサイズの上限、frontmatter の項目はクライアントとバージョンで違い更新も多いので、覚えている内容で答えず、[${CLAUDE_SKILL_DIR}/../../reference/sources.md](${CLAUDE_SKILL_DIR}/../../reference/sources.md) から公式ドキュメントで確かめる。

指示どおりに動かない原因を調べるときは、推測で直さず、クライアントが用意している確認手段（読み込まれたファイルの一覧、デバッグログ、セッションのログ）で、その指示がそのときどう扱われていたかを確かめる。調べた結果、仕様どおりの動きで設定した人の意図にも合っていることもある。その場合は、そう考えた根拠と、意図が違うなら何を変えればよいかを示す。ユーザーの指示がいつも正しいとは限らないので、エージェントが意図どおり動くかを基準にし、根拠を示して別の案を出す。

## 終わりの条件

原因を調べる依頼は、そのとき指示がどう扱われていたかを確認手段の結果か公式ドキュメントの記述を根拠に示し、直す案か直さなくてよい理由を出したところで終わる。確認手段を実行できない環境なら、何を実行すれば確かめられるかも示す。

書く・直す依頼は、変更したうえで、実際にエージェントを動かして期待どおりになったことを確かめたところで終わる。直した指示が正しいかどうかは、動かしてみるまで分からない。動かせない環境なら、どう試せばよいかを示す。試すときは次を見る。

- 使われるはずの依頼で使われ、関係のない依頼では使われないか。新しいセッションで試す。
- 失敗した事例をもとに書いた文は、その事例で試せばうまくいくに決まっている。同じ理由が当てはまる別の場面で試す。
- 構文のチェック、使用状況の確認、使われ方と出力の評価には、クライアントが用意しているツールを使う。
- 頼まれた範囲の外に書き足していないか。

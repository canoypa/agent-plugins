今の会話を、会話を見ていないエージェントが続けられるように記録に残す。読み手は、あとでこの作業を再開するエージェントか、`--fork` で起こす新しいセッションである。今の作業の全体を渡すことも、一部だけを切り出して渡すこともある。残すのは、知らないと読み手が間違えるか、ユーザーに聞き直すことだけ。経緯・解決済みの話・捨てた案は残さない。

記録には、今の状況と次の一手を書く（判断待ちなら、何を決めてもらうかと推奨）。この会話でユーザーに直されたことと、次に使うとよい skill も書く。読み手は会話を読めないので、ここに書かなければ同じ間違いを繰り返す。ほかの記録（ADR、作業ログ、issue、コミット）にあることは、写さずにパスか URL で指す。確かめていないことは、そうと分かるように書く。秘匿情報は伏せる。

置き場所はユーザーの指示ファイルに従い、書いていなければユーザーに聞く。同じ作業の記録がすでにあれば、新しく作らず、状況と次の一手を今のものに書き換える。

ARGUMENTS の `--fork` 以外の部分は、次に取り組むことの説明として扱い、それに合わせて絞る。それが今の作業の一部だけなら、その部分を切り出す。残りはこのセッションで続くので、切り出した部分の記録は元の記録とは別に作り、元の記録には切り出したことと記録の場所を書き足す。切り出した記録には、どこまでを受け持つか（それ以外は元のセッションに任せる）と、終わったら結果をどこに残すかも書く。

ARGUMENTS に `--fork` があれば、記録を書いたあと、続きを始める新しいセッションを用意する。`spawn_task` のように新しいセッションを起こすツールがあればそれを使い、なければ新しいセッションに最初に貼る一言を出す。どちらも文面は、最初に読む記録のパスと次の一手にとどめ、中身は記録に任せる。

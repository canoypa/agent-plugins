---
name: handoff
description: 今の会話の状況と次の一手を記録に残し、会話を見ていないエージェント（あとで再開する自分や、新しいセッション）が続きから始められるようにする。`--clear` を付けると、記録を書いたあとこのセッションの会話を消して、記録から続ける。`--sub` を付けると、作業の一部を記録に切り出して新しいセッションに渡す。
argument-hint: "[--clear | --sub <渡す作業>]"
disable-model-invocation: true
---

今の会話を、会話を見ていないエージェントが続けられるように記録に残す。読み手は、あとでこの作業を再開するエージェント、会話を消したあとのこのセッション、`--sub` で起こす新しいセッションのどれかで、どれもこの会話を読めない。残すのは、知らないと読み手が間違えるか、ユーザーに聞き直すことだけ。経緯・解決済みの話・捨てた案は残さない。

記録には、今の状況と次の一手を書く（判断待ちなら、何を決めてもらうかと推奨）。この会話でユーザーに直されたことと、次に使うとよい skill も書く。読み手は会話を読めないので、ここに書かなければ同じ間違いを繰り返す。ほかの記録（ADR、作業ログ、issue、コミット）にあることは、写さずにパスか URL で指す。確かめていないことは、そうと分かるように書く。秘匿情報は伏せる。

置き場所はユーザーの指示ファイルに従い、書いていなければユーザーに聞く。同じ作業の記録がすでにあれば、新しく作らず、状況と次の一手を今のものに書き換える。

記録を書いたあとにすることは、ARGUMENTS で決まる。何もなければ、記録を書いて終わる。`--clear` と `--sub` に要るツールがこのセッションに無ければ、記録だけ書いて、そのモードはここでは使えないとユーザーに伝える。

`--clear` は、同じ作業を、会話を消したこのセッションで記録から続けるためのもの。記録には今の作業の全体を書く。会話を消すと、記録の場所を伝える返答も一緒に消える。そこで、記録の絶対パスを `${CLAUDE_PLUGIN_DATA}/clear/` の下の、環境変数 `CLAUDE_CODE_HOST_SESSION_ID` の値を名前にしたファイルに1行で書いておく。会話を消したあと、この plugin の hook がそのファイルを読んで記録の場所をコンテキストに入れ、ファイルを消す。最後に、`clear_session` のようにこのセッションの会話を消すツールを、このセッションを指して呼ぶ。会話を消せなかったときは、書いたファイルを消し、記録の場所をユーザーに伝える。

`--sub` は、`--sub` に続けて書かれた作業を、新しいセッションに渡すためのもの。渡すのは今の作業の一部で、残りはこのセッションで続く。渡す作業の記録は元の記録とは別に作り、どこまでを受け持つか（それ以外は元のセッションに任せる）を書く。元の記録には、切り出したことと切り出した記録の場所を書き足す。そのあと、`start_session` のように新しいセッションを起こすツールで、このセッションの会話を渡さずに新しいセッションを起こす（`start_session` なら `initiation: user_asked`、`context: fresh`、`use_worktree: false`）。会話を渡すと、読み手が記録だけから始めるという前提が崩れる。新しいセッションは、このセッションと同じフォルダで動かす。別の worktree で起こすと、元のブランチのコミットも未コミットの変更も渡らない。prompt には渡す作業を、background には切り出した記録の絶対パスと、それを最初に読むことを英語で書く。権限のモードは指定せず、このセッションのものを継がせる。
